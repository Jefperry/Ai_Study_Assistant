Prompt templates for HuggingFace FLAN-T5-Small

Summarization prompt:
"Summarize the following text into 3-5 key points. Focus on the main concepts and important details:

{input_text}"

Flashcard generation approach (rule-based heuristics):
- Extract definitions: "X is Y" → Q: "What is X?" A: "Y"
- Extract concepts: "The main types of X include A, B, C" → Q: "What are the main types of X?" A: "A, B, C" 
- Extract processes: "To do X, you must Y" → Q: "How do you do X?" A: "You must Y"
- Extract relationships: "X causes Y" → Q: "What does X cause?" A: "Y"
- Extract key terms: Important vocabulary → Q: "Define [term]" A: "[definition]"

Pattern matching rules for flashcard extraction:
1. Look for definition indicators: "is", "means", "refers to", "defined as"
2. Find enumeration: "types of", "kinds of", "examples include", "such as"  
3. Identify cause/effect: "leads to", "results in", "causes", "because"
4. Spot processes: "steps to", "how to", "method for", "procedure"
5. Recognize key terminology and create definition-based questions

Target: Generate 4-8 high-quality flashcards per summary with varied question types.

- Header: Authorization: Bearer <token>

- Include: id, title, content, summary, flashcards, created_at

/summaries/<id> (DELETE):
- Header: Authorization: Bearer <token>
- Delete summary (owner verification only)
- Return confirmation message

AI Engine Configuration and Deployment Strategy

Primary AI Engine: HuggingFace with google/flan-t5-small
- Memory usage: ~500MB (production-optimized)
- Processing speed: 10-30 seconds per request
- Input limit: 10,000 characters maximum
- Model caching: Local model storage to avoid repeated downloads

Flashcard Generation Strategy:
- Rule-based heuristics for speed and reliability
- Extract key terms and definitions using pattern matching
- No additional model loading required (memory efficient)
- Consistent output quality regardless of input domain

Deployment Considerations:
- Memory limit: 1GB total (500MB for model + 500MB for application)
- CPU requirements: 1-2 cores sufficient for small scale
- Storage: 2GB for model cache + database
- Recommended platforms: Railway, Render (free tiers compatible)
- Alternative: Heroku with performance dynos

Performance optimization:
- Model loaded once at application startup
- Text preprocessing to maximize model efficiency  
- Implement request queuing for high concurrency
- Cache frequent similar requests (optional)

Production Configuration:
- Environment variables for model paths and limits
- Graceful fallback when model fails to load
- Health checks for AI service availability
- Monitoring for memory usage and response times
